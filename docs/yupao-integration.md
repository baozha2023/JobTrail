# 鱼泡直聘接入协议与验收（v2.3.0）

核验日期：2026-10-11。平台 `yupao`，适配器契约 1，数据库 v6，配置 v2。目标发行版为 v2.3.0，数据库 v6 与配置 v2 已定版；下列历史验收记录不代表版本已公开发布。官网链路、适配器自动化测试和完整产品验收分开记录。

## 官方协议

来源为 [官方登录页](https://www.yupao.com/web/login/) 和 [官网求职入口](https://www.yupao.com/)，使用隔离 Electron Session、系统网络配置及官网公开 PC 客户端。会话不进入 SQLite、配置或备份。以下只记录请求形状、状态及字段名，不保存认证响应、令牌、Cookie、票据或二维码。

| ---------------------- | --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |

API 的 PC 请求头包含 `reqsource/business: YPZP`、`packagename: yp.pc`、`packageversion: 9.36.0`、`runtime: PC`、`hybird: NO`、`signVersion: 1`、`request-source: java`、时间戳、随机 nonce 及官网公开请求签名。签名由公开客户端算法生成，不替代身份验证；不生成设备验证材料、不绕过网站验证码。SSO 只接受上表指定 HTTPS origin、路径和单个非空 ticket 参数，拒绝嵌入凭据、重复参数、额外参数和其他目的地。

官网微信二维码返回的图片位于 `https://stat108.cdqlkj.cn/r/`。适配器仅允许该 HTTPS 图片来源，沿用图片大小、重定向及取消校验；该域名不允许账号接口请求、Cookie 操作或页面导航。2026-10-11 应用实测发现缺少该规则导致图片被拒绝；CDN 另将 JPEG 标记为 `application/octet-stream`。已补充图片白名单，并在共享会话模块按 PNG/JPEG/GIF/WebP 文件签名识别通用二进制图片，未知类型仍拒绝。回归覆盖其他域名、路径、嵌入凭据与伪图片。

同日 APP 实测取得二维码后，尚未扫描的轮询返回 HTTP 200、业务码 10010016、`data: null`。适配器将其保持为等待，不重新延长有效期；未知业务码和验证业务码分别归为协议错误和验证阻断，避免误显示网络错误。

令牌返回后必须完成 SSO，读取该 Session 保存的 Cookie，再通过官方账号接口确认身份。每个搜索批次重新检查账号；取消、切换扫码方式、刷新和旧响应隔离复用现有管理器。未知业务码报协议失败；401/10160001 与 403/429 分别作为登录失效和验证阻断，不能转换为空结果。

普通启动后的后续实测发现，账号当前 `role.nowRole` 并非始终为 2。此前将非 2 角色当作验证阻断，导致已认证账号无法继续搜索；扫码完成后的同类异常又误显示为网络失败。登录判断现改为官方账号接口成功且返回有效正数身份，角色与认证状态分开；搜索权限仍由实际页面/接口验证，不自动切换官网账号角色。扫码收尾的账号错误保留协议错误或验证阻断分类。新增两种角色及收尾错误回归，修复后原隔离 Session 重新确认已登录，北京销售三批、原始 JD 与保存通过。

## 搜索与详情边界

首页通过 `homeSearchBox` 主搜索框提交，结果页使用 `jobRecPageSearchInput` 及城市控件。官网先渲染 HTML 再绑定 React 事件，必须等输入框事件就绪后操作。清空高级筛选会同时将城市改成全国，因此需恢复用户指定城市，或地点留空时捕获的官网默认城市；北京原始代码为 2，上海为 25。城市目录维护见 [城市目录](discovery-city-catalogs.md)。

官网服务端首屏会将部分 API 失败转换成空数组，因此不直接将其作为真实空结果。适配器在结果页重提当前条件，读取与关键词、城市、页码及空高级筛选相符的实际结构化响应。独立推荐接口不接受。连续页通过官网无限滚动控件加载，结束判断依赖官方 total，与去重、坏条目或薪资筛选后的数量无关。每轮三批、200 条整批边界和 90 秒预算沿用共享运行时。

结构化响应已经关联实际请求后，不以某张卡片是否出现在 DOM 中否定有效批次。实测曾因等待响应最后一条岗位渲染而超时，修复后由下一批的分页控件及对应页码请求继续核验；回归覆盖页面未渲染响应末条的情况。

岗位身份采用官方数值 jobId，规范 URL 为 `https://www.yupao.com/zhaogong/<id>.html`。搜索列表只在官方企业认证标记下采用公司字段；个人招聘者姓名不替代公司。保留日薪、时薪原文，是否排除由共享薪资条件决定。

官网会在结构化响应的标题等展示字段中返回关键词高亮 HTML，例如 `金蝶<span style='color:#0099ff'>java</span>开发工程师`。鱼泡适配器在列表和详情解析时将这些字段转换为纯文本，再交给共享入库流程：去除标签和脚本/样式内容、解码 HTML 实体一次，保留原文及段落换行。岗位 ID、URL 和查询条件不作 HTML 转换；Renderer 不渲染原始 HTML。此前实测漏查了标题高亮标记，导致标签被原样持久化，2026-10-11 根据用户截图修复。重启后新搜索使用修复后的解析；既有搜索的固定观察快照及已保存求职记录不作自动改写。

详情从当前岗位的 `ppJobInfo.fullData.detail` 读取原始 JD，并与可见原文核对后标记完整。`desc`、`infoSeoExtra.detail`、AI 总结、联系字段及推荐列表不作为 JD 来源；不请求付费解锁。岗位 ID 不匹配、验证、加载失败或普通 404 不作为下架依据。
