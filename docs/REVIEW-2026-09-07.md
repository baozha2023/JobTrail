# JobTrail 审查与 Windows 打包验证

日期：2026-09-07。版本：0.3.0。修改范围仅 JobTrail 副本，保留已有工作区修改及业务数据；未执行 Git 提交或远程发布。

## 结论

保留 Renderer → Preload → IPC → Service → Repository 的分层，数据库和文件权限留在主进程。此次重点修复应用身份、更新事务、文件与配置错误处理和安装布局；没有引入第二套更新框架或联网安装器。

## 修复内容

| 范围 | 问题与处理 |
| --- | --- |
| 任务栏图标 | 开发进程不再以 Electron 可执行文件路径作为应用身份；开发版使用 `zhiji.development`，安装版使用 `zhiji`。统一窗口图标、重启图标与重启命令，并嵌入 Rust 和 Electron PE 图标。 |
| 打包 | 锁定 Electron 43.3.0、electron-builder 26.15.3、electron-vite 5.0.0、Velopack 1.2.0；恢复缺失的依赖，使用对应 Electron ABI 构建 better-sqlite3。 |
| 安装与卸载 | 新增 Rust 根启动器、内嵌载荷安装器和临时 worker 卸载器。只支持当前用户一份安装，拒绝已有安装、危险路径和目录联接。 |
| 数据布局 | `.runtime/current` 存放可替换的程序；根目录存放配置、数据库和简历。卸载保留数据，清理自身快捷方式、注册项和开机启动项。 |
| 更新流程 | 主进程持有 UpdateInfo；检查、下载、应用互斥，未下载或目标不一致不得应用。退出期间拒绝重复操作，更新中转进程不争用单实例锁。 |
| Delta 基线 | 同一模块选定低于目标版本的最新 Full、下载具体文件、校验大小和 SHA-256。网络错误与无效数据停止构建，避免静默吞错和下载错误基线。 |
| 发布流程 | CI 与本地共用 release:win；删除重复打包、默认 Portable 分发和 continue-on-error；通过环境变量读取标签，避免将标签直接拼入 PowerShell 代码。 |
| IPC 与外部链接 | 限定登记主窗口及其 mainFrame，拒绝其他窗口/子框架；安装版不允许环境变量覆盖 renderer URL。外部链接统一归一化并由主进程限定为 HTTP(S)，公司官网只在系统成功接收打开请求后标记已读。 |
| 配置 | 文件读取错误向上返回，不误判为损坏而重置；损坏备份使用 UUID；原子替换失败保持内存和磁盘原值并清理临时文件。 |
| 简历文件 | 拒绝目录导入、路径穿越和存储目录联接；独占复制避免覆盖。数据库删除提交后，临时文件清理失败记录错误，保留临时文件而不错误报告记录未删除。 |
| 日程提醒 | 收到系统 show 事件才标记已发送；失败可重试；停止调度时移除回调，防止关闭数据库后访问它。 |
| 列表状态 | 全量岗位列表与筛选列表均避免旧请求结果覆盖新结果。 |
| 可维护性 | 默认状态/行业从重复 SQL 改为数据列表和预编译插入；展开压缩成一行的模板，加入 Prettier；删除完全相同的两份文档副本。移除重复 native rebuild 依赖和易混淆的 Node ABI 重建命令。 |
| 安装包体积 | 前端依赖已由 Vite 打包，移至开发依赖，避免额外作为运行时 node_modules 分发；安装包约减少 16.7 MB。 |

## 安装布局

```text
JobTrail/
  JobTrail.exe
  JobTrail-Uninstall.exe
  .jobtrail-root
  .runtime/
    Update.exe
    current/
    packages/
  config.json
  data/zhiji.db
  resumes/
```

桌面、开始菜单和开机启动均指向根启动器。卸载不递归删除整个 JobTrail 根目录。开发模式不会修改安装版的开机启动项。

## 验证结果

- `pnpm test`：发布基线 7 项、业务/IPC/配置/文件/提醒/更新/渲染状态 39 项全部通过。
- `pnpm typecheck`、Prettier 检查、生产构建通过。
- `cargo test --locked`：2 项路径/标记测试通过；`cargo clippy --locked --all-targets -- -D warnings`、rustfmt 通过。
- `pnpm audit`：0 项已知漏洞；`cargo audit`：0 项已知漏洞和警告。审计数据库状态仅代表验证时刻，不能证明代码绝对没有漏洞。
- `pnpm release:win` 成功生成真实离线安装包、Full 和 Feed；产物大小及 SHA-256 与 Feed 一致。
- 实际安装、根启动器启动、主进程 SQLite 加载、公司新增/修改/删除 IPC、中文与英文界面通过。
- 原生窗口 WM_GETICON 返回职迹图标；窗口属性存储读得 AppId=`zhiji`、RelaunchCommand=根 `JobTrail.exe`、RelaunchIcon=项目 icon.ico。
- ICO 包含 16/24/32/48/64/128/256 七种尺寸；Electron、Rust 启动器和卸载器均包含七份图标资源。
- 普通路径及含中文、空格、单引号的安装路径均通过；重复安装返回失败，未创建第二个目标目录。
- 多轮安装/卸载、保留数据后的重装通过；应用内卸载能退出应用，移除运行时、程序、注册项、快捷方式及开机启动项；配置、数据库和简历保留。测试结束未留下职迹/worker 进程。

本地证据位于忽略的 `dist/qa/`（smoke-result.json、taskbar-properties.json、window-icon.png、中英文窗口截图）。依赖审计及测试日志位于 `dist/`。

大小：181,849,600 字节。SHA-256：`b210a11f3f566b1304ae67d3b2dcaef9a7111c784e8424c7004026bce1aeee4d`。

```powershell
pnpm install --frozen-lockfile
pnpm test
pnpm format:check

cargo clippy --manifest-path native/bootstrap/Cargo.toml --locked --all-targets -- -D warnings
pnpm release:win
```

## 验证边界

- 本次未发布 GitHub Release，因此未执行公网跨版本升级/Delta 应用验证；已验证基线选择、校验、更新状态机和真实 Velopack 安装/卸载。
- 安装包尚未配置代码签名证书。
- 未做所有 Windows 版本、缩放比例、长期运行与系统通知策略的穷举测试。
- 新安装布局不自动迁移旧版原始 Velopack 安装目录；已有旧版数据应先备份再迁移。数据库维持项目现有 schema 8 约定，不擅自转换旧 schema 或删除用户数据库。
- 简历回收文件清理失败会记录错误并保留 `.trash` 文件，本轮未增加后台清理服务。
