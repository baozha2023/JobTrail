# 岗位发现

本文档定义岗位发现的产品行为、查询规则、数据边界及 UI／MCP 契约，更新于 2026-10-10。应用版本为 2.1.0，数据库目标版本为 v5，配置版本为 v1。数据库字段、索引及恢复校验见 [数据库文档](database.md)，跨进程接口以 `src/shared/job-discovery.ts` 为准。真实网站验收的日期与范围单独记录在文末。

## 功能与界面

岗位发现支持 BOSS 直聘、猎聘、智联招聘、前程无忧、国聘和实习僧，提供统一搜索、岗位详情、网页浏览、账号管理、搜索历史及保存求职记录。侧栏入口位于公司管理与智能体之间，名称右侧显示 Beta 标识；应用默认启动页为求职记录。

页面标题右侧依次放置“新搜索”“账号管理”和“搜索历史”。标题下方采用可拖动分隔的左右布局：

- 左侧上方为关键词、地点、搜索按钮、平台选择和薪资筛选，下方为岗位列表、数量、排序、刷新及分页。关键词与地点并排，搜索按钮和薪资筛选按钮位于下一行。
- 右侧从标题下方开始，占满剩余高度，显示选中岗位的详情或网页。展开左侧薪资筛选不改变右侧高度。
- 窄窗口在列表与详情之间切换，保留岗位选择和列表状态。

搜索区域只保留一个主按钮：没有列表数据时显示“搜索岗位”，有数据时显示“搜索更多岗位”；已有任务时始终沿原任务与原条件继续采集，即使结果为空也不另建任务。搜索期间显示旋转图标和“取消搜索”，可点击取消，不再显示独立的续查按钮。

提交期间禁用关键词、地点、平台勾选和薪资上下限；有效条件提交后持续锁定，任务完成、取消、请求失败或切换页面均不解锁。查看历史时展示并锁定该任务的原始条件。排序、翻页和展开薪资条件不改变查询条件，仍可操作。“新搜索”关闭验证和岗位网页、取消当前仍在进行的采集，清空条件、列表及详情，恢复默认排序、分页和已登录平台的默认勾选；旧请求的晚到结果不能恢复旧页面。历史记录和已保存的求职记录保留。重新打开客户端时页面也从初始状态开始；未通过本地条件校验时不锁定草稿。

“薪资筛选”右侧使用一个 warning 按钮显示人工处理提示，例如“猎聘 · 需要网站验证”。仅需要登录、会话失效、需要网站验证三种状态按首次显示顺序排队；同时出现时沿用来源顺序，一次显示一项。解析失败、网络错误等仍显示普通来源错误，不进入人工验证队列。窄窗口保持按钮同行，长提示可省略显示。主搜索区域只展示结果总数，不展示来源采集计数或任务状态标签。搜索历史展示各平台岗位数及异常原因，完整任务状态保留给诊断及 MCP。

人工提示按原因打开对应界面：“需要登录”和“会话失效”打开该平台的扫码弹窗，与账号管理右侧统一使用 `DiscoveryLoginPanel.vue`，不展示左侧账号列表。该组件负责二维码、登录方式、状态提示、刷新及额外验证按钮的展示与事件；`JobDiscoveryView.vue` 统一管理登录请求、轮询、取消、弹窗关闭及搜索恢复，不在两个入口分别维护登录状态。取消、过期和失败保留原提示；官方扫码确认后自动关闭弹窗，并请求复核原搜索。主进程以当前 attemptId 的已认证状态校验复核请求，不凭 Renderer 或已有账号状态认定扫码成功。“需要网站验证”才打开独立平台网页，优先使用受阻页面和对应 Session；重启或历史页面已释放时打开该平台的官方账号入口。用户完成网站验证后手动关闭窗口。

扫码成功和网站验证关窗共用后续复核与续跑调度：应用沿全局 FIFO 和平台串行队列，使用相同会话和原搜索条件对该平台执行无缓存复核。复核期间保留当前提示并显示加载状态；只有收到可解析的官方批次且页面不再显示登录/验证阻断、数据成功提交后才清除提示，并自动继续该平台本轮搜索。复核首批计入同一轮的三批、200 条整批边界及 90 秒预算，不自动开启无限新轮次或重跑其他平台。页面重建时从官方查询恢复并按身份去重，不保证直接跳至原中断页。确认的真实空批次同样有效。不会仅凭关闭窗口、Cookie 变化或验证码暂时消失判定成功；首批复核仍被阻断、网络/解析/保存失败时保留提示。续跑再次遇到验证则停止并显示新提示；取消、关闭处理流程、退出登录、维护及退出都会中止待复核和续跑。其他人工提示按队列展示，当前轮次结束后可处理下一项，不自动开窗。

岗位提示和扫码登录的额外验证共用 `VerificationWindow` 窗口管理器，统一窗口创建、页面隔离、导航限制、互斥和释放；岗位验证使用受阻页面的原始官方 URL 与同一平台 Session。两种业务分别判断后续结果：扫码流程重试二维码，岗位流程复核原搜索。同一时间最多打开一个人工处理窗口，重复点击只聚焦已有窗口。网站验证窗口由用户关闭后触发岗位复核；扫码弹窗由官方扫码确认触发岗位复核。下一平台的人工处理窗口由用户主动打开。切换搜索、打开账号管理、退出对应平台、取消任务、维护或退出时关闭窗口并取消复核。人工操作期间不让自动采集操控该平台的页面。验证成功只解除对应来源的阻断，不自动完成整个搜索或继续其他平台。

官网页面与可见原生窗口分离：原生窗口承载真正的 `WebContentsView`，在同一 Session 重新加载受阻地址，随后释放后台受阻页面；不重写网站脚本，也不注入业务 preload、应用标识或附加 URL 参数。官网自行调用 `window.close()` 只关闭其页面，可见窗口显示本地关闭提示，仍等待用户手动关闭，不触发复核；原生窗口意外销毁或程序取消不视为人工完成。保留真实 Chromium/Electron 标识，仅移除职迹、JobTrail、zhiji 产品名。扫码面板在本次官方登录确认后自动关闭，包括账号管理入口；后续复核失败不能让已完成的扫码面板继续显示。详情页及详情读取前的会话检查发现登录/验证阻断时，同样更新当前搜索的人工提示，详情受阻地址优先交给验证窗口。可见的扫码额外验证窗口不会因二维码过期或后续页面错误自行关闭，用户关窗后再按当前状态处理。

编辑新搜索条件时，平台勾选项以账号状态为准：仅 `authenticated` 的平台默认勾选并可操作，其余状态默认不勾选、灰色禁用。登录成功后自动勾选对应平台；退出、会话失效或需要验证时取消勾选并禁用。状态刷新保留用户对仍处于登录状态的平台所作的手动取消选择。条件锁定后，平台选择保持原查询值，账号变化只更新状态及登录提示，不改写查询；历史中的未登录平台也按原查询显示为已选且不可修改。未选择任何已登录平台时，界面不允许创建新任务。

账号管理与来源扫码弹窗的内容区域独立滚动；二维码保持正方形，并按内容区域可用高度限制尺寸，滚动到二维码时必须能完整显示，不得出现二维码始终被裁切的布局。弹窗标题、关闭按钮和左侧账号列表不随二维码区域滚动。

## 搜索条件

搜索条件仅包含关键词、可选地点、平台、最低月薪和最高月薪。

| 条件           | 规则                                                                                           |
| -------------- | ---------------------------------------------------------------------------------------------- |
| 关键词         | 必填，去除首尾空白，长度不超过 100 字符，通过各平台官方主搜索框提交。                          |
| 地点           | 默认空，可清除，无“全国”选项。指定地点通过官方地点控件提交；留空沿用网站默认地点，不表示全国。 |
| 平台           | 至少选择一个，可同时选择六个平台。                                                             |
| 最低／最高月薪 | 可分别省略，单位为人民币元；同时填写时最低值不得高于最高值。                                   |

地点目录按平台分别存储在 `src/shared/discovery-cities/`，保留各平台完整的城市级选项、官方代码和控件名称，由共享模块集中登记。运行时仅对当前所选平台按源数据中已统一的城市名称字符串精确匹配计算交集，不联网获取目录。选一个平台显示该平台全部城市；未选平台禁用城市选择器；没有共同城市时提示原因，仍允许留空使用平台默认地点。列表单级、可搜索、可清空、去重，四个直辖市优先，其余按首字母和规范名称排序。目录来源、核验方法和数量见 [城市目录维护](discovery-city-catalogs.md)。

城市选择器和搜索历史标签随应用语言显示中英文名称，两种语言下均可用中文或英文搜索城市。英文译名集中维护，同音英文名称加省份区分。语言切换只更新显示，不清空已选城市；提交、交集、MCP 城市列表及历史存储继续使用规范中文名称。历史别名可显示对应译名，无法识别的旧名称原样展示。

可编辑状态下，所选平台集合发生任何增减都同步清空城市和选择器搜索文字，包括账号状态变化导致的自动增减；相同集合的轮询刷新或顺序变化不清空。历史条件回填和已锁定搜索不受影响。新搜索的 Service 校验非空城市在所有所选平台中指向同一地区，不合法时返回 `DISCOVERY_UNSUPPORTED_CITY`，不创建任务；UI 和 MCP 共用此规则。历史查询保留原字符串，继续采集时若某个平台已不支持该城市，在访问缓存和官网之前报告该来源 `unsupported_city`，不回退或改写查询。`capabilities.cities` 始终返回对应平台自己的完整城市名称。

关键词和地点通过网站实际搜索请求提交，不按岗位文字再次筛选关键词，保留官网语义搜索结果。仅在确认存在广告的平台 adapter 中处理广告混入，不对六个平台统一增加城市过滤。前程无忧已观察到带 isPromotion 标记的异地广告，由其 adapter 按 jobAreaString 的城市部分检查，排除不符合指定城市的岗位；未选城市时不做地点过滤，符合搜索条件的推广岗位可保留。猎聘已有地点规则继续由自身 adapter 负责；实习僧的异地结果按用户要求由其 adapter 在入库前过滤，未选城市不做地点过滤。Repository 和客户端不重复过滤城市；薪资仍在入库前统一校验。保留官方主搜索列表的关键词相关匹配，排除独立推荐区域。查询前清除网站残留的高级筛选，并核验实际提交的条件。经验、学历、招聘类型和用工类型属于岗位展示信息，不作为搜索条件；实习僧的平台接入范围固定为实习岗位。

## 薪资准入与表示

薪资范围统一在入库前判断，不向平台下发远程薪资条件。任一上下限有值即启用筛选，采用区间相交规则，边界相等视为符合。

- 人民币月薪直接比较；人民币年薪除以 12 后比较，不按“13薪”等发薪月数调整。
- 单一金额按确定值比较，不把缺失上限解释为无限大。
- 日薪、时薪、外币、面议及无法可靠归一的薪资，在启用筛选时排除，并记录原因。
- 未设置薪资范围时，通用薪资准入不因薪资类型、缺失或解析失败而排除岗位。BOSS 适配器先检查会话：有效岗位缺少薪资文本时按会话失效处理，当前批次不入库。
- 被排除的新候选不新增岗位、观察或结果关联，也不删除其他搜索及求职记录中的既有数据。

观察保存薪资原文 `salary`，结构化数值仅包含人民币标准月薪下限 `salaryMin` 和上限 `salaryMax`。币种、周期、薪数及折算标记用于解析，不持久化。

| 原文示例                             | salaryMin | salaryMax |
| ------------------------------------ | --------: | --------: |
| 15–25K/月                            |     15000 |     25000 |
| 15000元/月                           |     15000 |        空 |
| 24万元/年                            |     20000 |        空 |
| 日薪、时薪、外币、面议或无法可靠归一 |        空 |        空 |

界面显示薪资原文。薪资排序使用上限，单值使用下限，不可比较值置后，同值按固定次序排列。

BOSS 搜索响应中，只要可解析的有效岗位缺少 `salaryDesc`、其值为空白或不是文本，就暂停该平台并显示“BOSS 直聘 · 会话失效”，点击进入扫码登录流程；已保存的批次保留。明确返回“面议”属于有效薪资文本，真实空列表不触发失效，非空列表全无有效岗位仍归入解析错误。当前查询响应已证实登录或验证阻断时，后续找不到搜索控件不会将其覆盖为“查询范围未验证”；其他真实条件核验错误仍保留原分类。

## 平台采集与任务执行

查询链路为：官方搜索 → 适配器逐条解析、去重及城市准入 → 标准化及薪资准入 → 整批事务入库 → SQLite 分页 → UI／MCP 展示。

### 适配器边界

`PlatformAdapter` 是平台功能的唯一接入契约。每个平台的业务实现集中在 `src/main/discovery/adapters/<平台>.ts`，包括：

- 官方搜索控件、条件提交、请求响应关联、字段解析、城市准入及分页。
- 岗位链接规范化、平台岗位 ID 提取、平台域名边界。
- 详情读取规则、账号登录证据、登录限制、安全验证和岗位下架识别。
- 二维码获取、轮询、确认、失效状态、接口请求头、协议解码和中英文扫码说明。
- 官方验证入口、验证页识别、允许的验证跳转、请求标识和来源地址。
- 账号检查地址、远程条件能力和独立的缓存契约版本。
- 自身城市目录与代码查询，通过 `PlatformAdapter.cities` 提供给 Service、运行时和能力查询。

每个 adapter 只导入自己的城市 JSON；通用索引、别名和交集算法位于不依赖平台注册表的 `discovery-city-catalog.ts`。`shared/discovery-cities.ts` 仅为 Renderer 提供城市选择元数据，Main 不通过它查询网站能力。公共平台名称、输入输出契约和历史数据库版本枚举仍留在各自公共层，不把 Main 网站实现导入 Renderer。

| 文件                    | 查询与分页依据                                                                                                                                                      |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `adapters/boss.ts`      | 官方搜索框和城市控件，`joblist.json` 请求的 query/city/page，滚动加载与响应 hasMore。                                                                               |
| `adapters/liepin.ts`    | 官方搜索框和地点控件，`pc-search-job` 的 key/dq/currentPage，官方分页控件。                                                                                         |
| `adapters/zhilian.ts`   | 官方搜索框和地点弹窗，搜索场景的关键词、城市与 pageIndex；条件一致的首屏 SSR 数据和续页搜索响应。                                                                   |
| `adapters/wuyou.ts`     | 官方搜索框和地点弹窗，清除地点后单选，`search-pc` 的 keyword/jobArea/pageNum，官方下一页。                                                                          |
| `adapters/iguopin.ts`   | 官方搜索框和地区弹窗，`/api/jobs/v1/recom-job` 中 `search.keyword/district/page`，响应 `page/page_size/total` 与官方下一页；仅收录 `index=iguopin` 的国聘官方岗位。 |
| `adapters/shixiseng.ts` | 官方实习搜索框和城市控件，`/app/interns/search/v2` 的 `keyword/city/type=intern/page`，响应总数、批次大小与官方下一页；不接收校招及独立推荐接口。                   |

共享层仅执行与网站无关的机制：浏览器和 Session 生命周期、安全边界执行、响应监听、DOM 操作、受限二维码请求与 Cookie 写入、取消与轮询、任务队列、去重与异常隔离、薪资标准化、事务和 SQLite 分页。公共 DOM 读取器接受适配器提供的选择器；适配器也可提供独立的页面脚本。共享层不包含具体平台 ID、网站域名、接口地址或按平台判断的业务分支。

二维码协议实例按登录尝试隔离。协议只获得受限请求和 Cookie 写入能力，不持有 Session、窗口或数据库。取消、失败、过期和登录完成时释放协议；已取消请求的晚到响应不得写 Cookie 或改变新尝试的状态。只有适配器提供并验证过的官方验证能力才可打开验证窗口。用户手动关闭扫码期间的额外验证窗口后，按原登录方式和同一 Session 自动重新申请二维码，保留 attemptId，使已有界面轮询继续收到新二维码；仍须等待官方扫码确认。程序关闭、切换平台、意外销毁和网站自行关页不触发自动申请，关闭窗口不视为登录成功。

二维码站点请求头全部由适配器声明，共享层不添加 `X-Requested-With` 等站点默认头，仅根据请求体编码设置 `Content-Type`，并按名称不区分大小写合并适配器与单次请求声明。BOSS、猎聘、智联、前程无忧和国聘显式声明 `X-Requested-With`；实习僧只声明官网的 `Origin`、`Referer`，不需要删除共享默认头的例外机制。

`adapter-registry.ts` 只负责适配器注册，不承载网站规则；产品代码仅通过该入口选择平台。适配器及其子目录不得直接或经共享模块引入其他平台实现、其他平台目录、全平台注册表、调度器、数据库或窗口管理器。架构测试递归检查依赖，包含普通导入、再导出、动态导入和 require，并检查运行时依赖无环。独立的只读诊断脚本和测试可直接调用对应 adapter，但不得在产品中另建平台分支。

适配器返回统一岗位、字段来源、实际条件、源页码、原始／有效／重复／异常数量和结束证据。共享批次模块接收适配器的岗位身份规则和准入函数，只处理去重、逐条异常隔离和日志，不自行决定某个平台的城市策略。

### 新增平台

1. 在 `adapters/` 新增一个实现完整 `PlatformAdapter` 的文件，包含该网站的搜索、详情、身份、登录及验证协议。
2. 在 `src/shared/job-discovery.ts` 的 `platformNames` 登记稳定 ID 和显示名称，在 `adapter-registry.ts` 登记适配器。平台类型、输入校验、选择框、账号卡片及 MCP 平台枚举从公共登记派生，无需逐处增加分支。
3. 在 `src/shared/discovery-cities/` 增加该平台独立的完整目录并登记到共享城市模块，记录官方来源、核验日期、已移除行政后缀、统一别名的规范城市名称和本站控件信息；无需补齐或缩减其他平台的城市。验证仅当勾选新平台时才影响城市交集，不能运行时猜测或静默替换城市。
4. 增加该平台的协议、身份、页面状态、取消和真实搜索验收。账号说明由适配器返回，Renderer 不增加专属文案键。改变解析或分页语义时更新该适配器的 `contractVersion`。

新增平台不需要修改搜索调度、二维码管理、详情服务、入库和分页流程。采集并发独立于已注册平台数量，最多四路，额外来源按队列执行。数据库 v4 已发布并冻结；国聘和实习僧接入通过 v5 及正式 `4 → 5` 迁移扩展平台约束，注册不能绕过持久化校验。每个数据库版本只接受对应的明确结构和接口，不接受开发中间态。

只有属于当前关键词、地点和页码的响应可被接收。条件无法确认、响应结构变化、翻页失败、登录限制、安全验证、超时和网络错误均返回明确来源状态，不能表示为成功的空结果。一个来源失败不撤销其他来源已保存的结果。单条岗位解析失败仅跳过该条并记录脱敏日志，不提示用户、不拒绝其他有效岗位。“页面解析未完成”仅用于当前响应无法按约定识别，或非空列表中没有任何可解析的有效岗位身份；真实空列表、部分坏条目及城市/薪资过滤后无结果不触发该警告。已提交批次的结果保留。“平台响应超过读取限额”“岗位批次数量校验失败”及响应体读取失败归入“网站请求失败”，保留各自固定原因用于诊断。

任务遵循以下规则：

- 全局 FIFO 调度，同平台串行，最多四个平台并行。
- 每轮 90 秒，每平台最多三批；200 条有效候选作为整批边界停止预算，按城市和薪资过滤前可解析、批内去重后的候选数量计算。已返回的批次完整处理。
- 整批岗位与来源进度在同一事务内保存，成功后推进游标；保存失败保留待提交批次。
- 连续两批来源身份无新增、且无明确结束证据时标记部分完成。全部候选被城市或薪资过滤不构成分页结束或无增长。无增长判断使用过滤前的来源身份；非空批次全部条目解析失败时停止该来源并报告解析错误，不据此宣称网站已结束。
- 取消保留已入库结果。重启将未完成任务标记为中断，不直接复用失效的浏览器游标。

列表缓存有效期为两分钟，保存连续批次，按平台、关键词、地点、薪资条件、会话代次及适配器契约隔离。浏览器查询上下文在采集轮次之间保留；上下文失效时重新提交官方查询，按来源身份去重恢复，并返回恢复状态。

“搜索更多岗位”使用同一任务和条件继续下一轮采集，不批量补全详情。来源的已提交页码或游标决定下一批；网站结束由响应或分页控件证据确认。适配器可以使用官方响应提供的总数和分页大小判断剩余页，不用当前批次实际条数猜测网站总量或结束位置。

## 结果展示与稳定分页

搜索期间，界面约每 1.6 秒读取任务和数据库结果。各平台整批入库后即可显示，不等待所有来源完成。界面翻页只读取 SQLite，不触发网站采集。

界面的 `discovery:list` 与 MCP 的 `list_discovered_jobs` 共用 `JobDiscoveryService.list()` 和同一套 Repository 查询，均支持相关性、月薪和发现时间三种排序。首次读取结果建立浏览视图 `viewId`，并固定岗位序号和观察版本。后续新增岗位追加到末尾；采集结束、详情补全不自动重排已有岗位或改写视图观察。

相关性采用本地通用 BM25F 文本排序，不使用行业、编程语言或岗位专用词库，不调用模型。统一全半角与大小写，按词识别拉丁文本，中文使用通用分词及低权重双字片段补充复合词匹配。查询词去重；词语区分度（IDF）由本次搜索结果的观察版本统计，常见词自动降低权重。标题、公司名、已有职位描述的字段权重为 5、2、1，按各字段文本长度归一化、限制重复词频，并增加查询覆盖、标题短语顺序及完整标题匹配的权重。未读取的详情不臆测、不主动抓取；不存在关键词匹配的结果仍保留。分数仅表示本次搜索中的文本相关性，不代表简历匹配度，也不跨搜索比较。

创建相关性视图时重新计算当前结果分数，因此历史搜索刷新后也会使用当前算法。已有视图出现新岗位时，以当前结果统计给新增项排序并追加；原有序号与观察版本不变。没有新增的轮询及翻页不重复计算。排名分析逐条读取观察，只保留词频等数值特征；最终排序、计数与分页仍由 SQLite 完成。

- 主动刷新或改变排序建立新视图并回到第一页。
- 每页支持 10、20、50 条，默认 20 条；改变每页条数保留视图并回到第一页。
- 后续页必须携带相同 `viewId`，同一视图不能改变排序。
- 省略排序参数时沿用已有视图排序；仅创建新视图时默认按相关性排序。
- 计数与分页使用相同视图条件，不执行关键词、地点或薪资筛选。
- 不同客户端可继续读取各自视图；所属搜索历史删除时一并清理。

## 岗位身份、观察与详情

岗位身份优先使用平台岗位 ID，缺少 ID 时采用平台规则验证的规范 URL。同平台按身份去重，跨平台不自动合并，仅提示疑似重复。猎聘普通岗位与校园岗位区分身份；平台 ID 中的合法字符原样保留。

岗位观察不可变，搜索结果和浏览视图引用具体观察版本，岗位持有当前观察引用。完整标题、公司和城市生成非唯一指纹，通过索引查找跨平台疑似重复；字段不完整时不生成指纹。

只有用户打开某个岗位时，界面才使用 `mode=ensure` 按需读取详情。共享 Service 根据岗位当前观察的详情时间复用三十分钟缓存，不能用固定视图中的旧观察判断缓存有效期；有效缓存无需启动桌面浏览器。`mode=snapshot` 只读取指定观察，`mode=refresh` 强制读取网站。首次搜索、后台轮询、翻页和列表刷新不自动选择岗位或读取详情。单次网站读取预算为 25 秒。列表刷新保留已读完整 JD，不延长详情缓存有效期。

详情显示岗位、公司、地点、薪资原文、经验、学历、JD、来源和读取时间。缺失原因区分未登录、会话失效、网站验证、平台未提供、解析失败及尚未读取详情。切换岗位后，过期响应不得覆盖当前选择。

登录和验证的页面文字证据只取可见且位于 JD、推荐区域之外的内容，避免把职责描述中的“安全验证”等文字误判为网站阻断。可见性检查元素尺寸、可见状态，以及元素和祖先的 `display`、`opacity`；透明或隐藏容器中的预加载验证码不构成阻断。真实验证标题、网址和可见验证码 iframe 仍独立检查，不因存在隐藏预加载组件而忽略真正显示的验证。完整 JD 可以包含滚动区域外的正文，不按当前视口裁剪。

列表摘要即使包含 JD 文字，也保留未读取完整详情或被阻断的原因。读取完整 JD 后，仍保留适配器逐字段报告的解析失败原因，不将其改写为“平台未提供”。详情请求结束后同步当前搜索的来源状态；已完成且停止轮询的搜索遇到新的登录或验证阻断时，也立即显示人工处理提示，包括详情请求失败的情况。网页模式切换岗位立即导航，不依赖详情读取成功。

详情补全生成新观察并重新标准化。若薪资不符合当前搜索条件，保存新观察并移除当前结果关联；旧视图仍可读取和保存其固定观察，刷新后应用变化。

### 岗位下架

实际读取详情时，只有同一岗位的明确状态节点表示下架、关闭、失效、过期或删除，才执行下架清理。JD 正文、推荐区域、登录页、验证码、网络错误、空白页、泛化 404 和跳转到其他岗位不能作为下架证据。

确认下架后，在同一事务中删除发现岗位、全部观察、搜索结果、浏览视图条目及保存来源关联，重算相关来源数量。已有求职记录和公司保留。

界面立即移除左侧岗位，右侧只显示“已下架”，不自动选择其他岗位。当前页为空时回到最后一个有效页，其余岗位顺序和固定序号不变，序号允许留空。当前运行期间拦截该身份的旧批次并清理缓存，防止旧响应重新写入。MCP 返回 `DISCOVERY_JOB_OFFLINE`。缓存详情不代表平台实时状态，清理仅发生于实际读取并确认下架时。

## 保存与历史管理

保存岗位时，用户选择已有公司或确认新建公司，指定现有状态及可选简历。公司、求职记录和来源关联在同一事务中保存。重复保存同一来源岗位返回既有关联；后续采集不覆盖用户编辑。不推断公司行业，也不将岗位工作地点写成公司办公地点。

已有公司下拉框默认提供全部公司，支持用户输入公司名搜索，不按招聘网站公司名预先过滤或限制为前 20 条。打开弹窗时，若招聘网站公司名与已有公司名完全相同，则默认选中该公司；否则保持未选择，由用户自行选择或确认新建。默认选中后仍可搜索并改选其他公司。

桌面加入求职记录成功后，顶部立即显示“已加入求职记录”的成功提示，并刷新求职记录表格、关联选项和公司数据，保留表格当前的筛选条件与有效页码；切回求职记录页面即可看到更新，无需手动刷新。

搜索历史保存查询条件、实际远程条件、来源状态及结果观察版本，支持查看、单次删除和批量删除。进行中的任务先取消再删除。关键词旁仅显示非空地点标签，不显示任务状态标签。平台明细保留平台名称和岗位数量，仅在需要登录、会话失效、需要网站验证、此城市尚未支持、查询范围未验证、页面解析未完成、超过本轮时间预算、网站请求失败这八种异常状态下追加原因；不显示排队中、搜索中、完成、部分完成、已取消、已中断。其中 `parse_error` 且原因为 `authentication_check_inconclusive` 时，搜索页与历史统一显示“登录状态复核未完成”，不显示为岗位页面解析失败；复用已有状态和原因字段，不改变数据库契约。

删除历史同时删除所属浏览视图，再按实际引用回收岗位和观察。搜索结果、旧视图、保存关联及仍有业务引用的岗位当前观察属于有效引用；当前观察指针不能使孤立岗位永久保留。历史清理不删除求职记录，求职记录删除后的来源关联清理同样触发引用回收。

## 账号与会话

登录复核使用各平台真实账号控件：猎聘识别个人页头部的登录头像，智联识别首页个人账号区的头像，前程无忧使用 `https://we.51job.com/pc/search` 上的非空账号姓名。前程无忧官网首页可能在搜索会话有效时仍显示登录表单，不能用它代替搜索入口的账号复核。隐藏账号区、空姓名占位和无关头像不构成认证证据；可见登录表单与网站验证仍优先阻止采集。

账号管理和搜索历史弹窗固定为窗口宽 70%、高 80%。账号管理左侧六个平台以三行两列排列，右侧显示所选平台二维码或账号状态，底部为关闭按钮。每个平台支持一个账号。

账号卡片提供“查看状态”（未登录时为“扫码登录”）和“退出登录”。退出登录按钮与状态按钮尺寸一致，有边框、背景透明。已登录面板显示成功状态和上次确认时间。

点击扫码登录时请求平台二维码，面板显示二维码、扫码说明和适配器提供的扫码方式。国聘提供 APP 扫码和微信扫码，默认 APP；实习僧仅提供微信扫码。账号管理和搜索中断后的扫码弹窗共用面板，启动请求可携带 `method`，返回状态包含当前及可选方式，后台拒绝平台不支持的方式。其他四个平台保持原有默认协议。

刷新、切换扫码方式、切换平台、关闭弹窗和清除会话均取消旧请求，旧尝试的晚到结果不得写入认证材料或覆盖新状态。登录成功依据适配器校验的官方认证证据；国聘和实习僧还必须取得官方账号接口返回的有效个人身份。扫描成功、窗口关闭、Cookie 存在或网页可访问均不能单独作为登录依据。绑定账号和额外验证由用户在官方流程中完成，未完成前保持待处理状态。

客户端要求所有平台登录后才能实时采集，官网允许匿名浏览也不例外。后台统一限制搜索、继续搜索、实时详情和内嵌网页入口，直接 IPC、MCP 和界面遵循相同规则。六个平台在每次搜索、继续搜索、实时详情／网页入口统一通过 `account-session.ts` 调用 adapter 的必需 `checkSession`，复核频率由 adapter 的必需 `sessionCheck` 声明。国聘、实习僧的搜索接口可匿名返回数据，因此保留每批次调用官方账号接口的严格检查；原四个平台每次操作检查各自官方页面的登录证据，轮内各批次继续检查搜索响应中的登录与验证限制。明确失效时暂停该来源并提示重新登录，其他来源继续；检查无结论时阻止实时操作并保留上次有效确认时间，不把网页可访问当作登录成功。显式刷新账号状态会实际检查六个平台，不因本地旧状态为未登录而跳过。账号校验网络或协议异常阻止本次采集，但不凭异常撤销已有登录确认，也不放行匿名请求。历史列表、已保存快照和有效详情缓存仍可读取。

猎聘要求人工验证时提供“打开猎聘验证”。用户主动打开官方窗口，手动关闭后按原登录方式自动重新申请二维码；保留当前 attemptId 与 Session，关窗不代表登录成功。程序取消、切换平台、网站自行关页和意外销毁不触发重新申请。验证窗口使用官方 URL，不添加应用后缀，网站自身参数原样保留。各平台 Session、页面和两类验证窗口的 User-Agent 不含职迹／JobTrail／zhiji 产品名，保留真实 Chromium／Electron 版本；远程页面不提供业务 preload、不注入应用标识，窗口标题仅使用网站名称或标题。前程无忧二维码 JSONP 使用中性回调名 `callback`，不在请求参数中携带应用名称。不自动完成或绕过网站验证。

Chromium 将认证材料保存在 `browser-sessions/<platform>`。Cookie、LocalStorage 和 IndexedDB 不写入配置或业务数据库，不进入可移植备份；二维码和临时认证响应不写入诊断日志。数据库仅保存平台状态、证据、确认时间和会话代次。

普通重启保留确认状态，界面显示“已登录”；搜索遇到登录失效或验证限制时提示用户处理。备份恢复撤销导入的确认状态，复核本机会话。退出登录经确认后停止该平台采集、释放页面并清除其本地 Session，不自动请求新二维码。

官方扫码确认成功时递增会话代次，后续搜索不复用匿名或旧账号的查询缓存。普通页面状态复核保留当前代次。

## 内置浏览器与安全边界

右侧岗位网页使用 Electron `WebContentsView` 和应用自带 Chromium，在详情与网页模式之间切换。网页模式占满整个右侧面板，包括原岗位标题与底部操作区，不保留内边距；详情切换、返回、前进、刷新、外部打开及加入求职记录统一放在左右面板上方的同一行工具栏，整组靠右紧邻排列，不将浏览操作与保存按钮分散到两端，不提供放大、缩小按钮。窄窗口返回列表也使用此工具栏，空间不足时工具栏可横向滚动。切换岗位保留当前模式并导航至新岗位。

后台采集使用隐藏 `BrowserWindow`。同平台登录、验证、采集和岗位网页共享 Session，页面实例独立。远程页面不加载业务 preload，关闭 Node 集成，开启上下文隔离和沙箱，拒绝权限申请及下载，限定平台导航与请求 URL。

公共网络校验允许的 URL 长度上限为 10240 字符，超过上限仍拒绝；仅允许 HTTP/HTTPS 和 80/443 端口，禁止内嵌凭据。招聘平台请求的 DNS、代理与连接交由系统网络配置和 Chromium 处理。URL 长度与响应体读取限额、岗位采集批次预算分别校验。

Vue 上报网页占位区域和固定浏览操作，由 Main 管理原生视图。弹窗、下拉菜单和页面切换协调隐藏或恢复原生视图，防止遮挡应用控件。

详情页使用“打开网页”按钮进入网页模式。创建网页及页面实际加载期间，右侧居中显示转圈和“网页加载中…”；加载结束或失败后停止转圈。切换岗位时，在新岗位账号检查前释放旧网页，检查失败不得在新选择下重新显示旧网页。Main 依据原生网页的加载事件通知界面，刷新、前进、后退及网页内跳转遵循同一状态；加载期间原生视图隐藏，避免覆盖提示。打开操作携带独立请求标识，旧网页的晚到事件不能影响新网页或已关闭的界面；订阅随组件卸载释放。

### 发布约束

所有平台 Session 由 `account-session.ts` 在首次使用前设置 `mode: 'system'` 并关闭旧连接，初始化完成后才交给调用方。账号接口、二维码、页面、子资源、Service Worker、详情及验证窗口共用各自的平台 Session。DNS、系统代理/PAC、TLS 证书与连接策略由 Chromium 处理；产品代码不再提供本机转发代理、额外 DNS/DoH、手工 CONNECT、IP 替换、强制直连或 WebRTC 网络覆盖。

Session 初始化、存储刷新和连接释放统一由 `AccountSessions` 管理；并发初始化只执行一次，失败可重试，不清除已有登录数据。备份、更新和退出排空任务、释放页面并保存 Cookie 后关闭连接，恢复时沿用系统配置。平台域名、URL、页面隔离、权限、响应体限额及取消仍分别校验。单元测试覆盖初始化、失败和生命周期；`test:discovery:local` 在隔离安装中检查六个平台的系统配置，并用临时本机服务验证 Chromium 请求、页面、Service Worker、Cookie、TLS、重定向和取消，不改变 Windows 设置、不访问真实招聘网站。

六个平台的验收状态按链路分别记录。国聘、实习僧的既有登录会话已通过官方账号校验、真实搜索、续查、完整 JD、网页和保存验收；这不代表扫码确认、绑定和人工验证的全过程均已验收。原四个平台仍有未完成的真实链路，详见文末 [验收记录](#验收记录)。合成页面、二维码解码、单个平台的列表成功均不能替代完整平台验收。

## 数据库与生命周期

数据库 v5 沿用 v4 引入的十张岗位发现业务表：

| 表                       | 职责                                                         |
| ------------------------ | ------------------------------------------------------------ |
| `discovery_jobs`         | 来源身份、规范 URL、当前观察及疑似重复指纹。                 |
| `discovery_observations` | 不可变的原始字段、标准化字段、字段来源、缺失原因及读取时间。 |
| `discovery_runs`         | 查询条件、任务状态和搜索历史。                               |
| `discovery_requests`     | 请求 ID 与任务的幂等映射。                                   |
| `discovery_sources`      | 各平台进度、实际条件、批次统计、游标和错误。                 |
| `discovery_results`      | 当前任务准入岗位、观察引用及相关性。                         |
| `discovery_views`        | 搜索浏览视图、排序和创建时间。                               |
| `discovery_view_items`   | 视图内固定序号、岗位及观察引用。                             |
| `discovery_platforms`    | 平台确认状态和能力信息。                                     |
| `discovery_saved`        | 发现岗位与求职记录的保存关联。                               |

观察 JSON 上限为 128 KiB UTF-8 字节，写入、数据库约束和备份恢复采用相同边界。超限明确失败，不截断 JD 后标记为完整详情。关联完整性由 Service 事务和恢复校验维护，不使用数据库触发器或物理外键。

结构、引用和来源计数校验在同一 SQLite 读事务快照中完成，允许 MCP 在另一个连接提交数据时安全启动桌面。

正式数据库 v1／v2／v3／v4 沿 `1 → 2 → 3 → 4 → 5` 的注册迁移链升级到 v5。`4 → 5` 仅扩展 `discovery_jobs`、`discovery_sources`、`discovery_platforms` 的平台 `CHECK` 约束以允许 `iguopin` 和 `shixiseng`，保留字段、索引和既有数据。产品只接受各版本对应的字段契约，不包含未发布结构之间的兼容接口或启动自动修补；迁移规则见 [数据库与配置文件长期维护和升级指南](persistence-upgrade-guide.md)。

数据库升级与旧备份恢复中的跨版本处理，统一由数据库和配置文件各自的版本链负责。启动升级与备份导入共用迁移和校验入口；备份层只负责归档、完整性检查和恢复协调，不另写业务数据转换层。配置版本与备份封装版本保持 1，不创建空迁移；未来版本、缺失迁移链及降级明确拒绝。已发布 v1—v4 契约冻结，v2.1.0 最终定版为六平台 v5，不兼容开发中间态、不增加 `5 → 5` 修补；后续持久化变更另行递增版本。

备份、恢复、升级和退出前停止任务准入，取消并等待采集及扫码，关闭页面、刷新 Session，再执行数据库流程。

## MCP 与智能体

UI、外部 MCP 和内置 Agent 共用 `JobDiscoveryService` 及工具注册表。查询、薪资准入、分页、详情和保存规则一致。

| 工具                      | 契约                                                                                                                                                                       |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `get_job_platform_status` | 获取平台状态、能力和限制；`check=true` 主动复核。                                                                                                                          |
| `start_job_search`        | 接收关键词、可选地点、平台和可选薪资范围，按 `requestId` 幂等创建任务。                                                                                                    |
| `get_job_search`          | 获取任务状态、来源进度、实际条件、覆盖及错误。                                                                                                                             |
| `list_discovered_jobs`    | 按 `runId`、`viewId`、排序和分页参数读取结果，不执行业务筛选。                                                                                                             |
| `continue_job_search`     | 按同一条件继续下一预算轮。                                                                                                                                                 |
| `cancel_job_search`       | 取消指定任务，保留已保存结果。                                                                                                                                             |
| `get_discovered_job`      | `mode=snapshot` 读取指定观察；`mode=ensure` 按需补全并复用最新有效详情缓存；`mode=refresh` 强制重新读取。支持 `viewId`／`observationId`，返回 `removedFromCurrentSearch`。 |
| `list_job_search_history` | 分页读取本地历史，不要求桌面运行。                                                                                                                                         |
| `save_discovered_job`     | 经 MCP 写入确认后，事务保存公司、求职记录及来源关联。                                                                                                                      |

实时操作通过 Windows 命名管道交给 Electron Main，通信绑定安装目录、协议版本和每次启动的随机令牌。优先连接已打开客户端，不改变窗口状态；无可连接客户端时才通过根启动器启动到托盘。并发启动合并，子进程清除 `ELECTRON_RUN_AS_NODE`。

实时采集不进入普通本地只读工具并行集合。MCP 不暴露 Cookie、二维码、任意页面脚本或浏览器控制。人工登录和验证返回平台提示及恢复指引，不无限等待。工具以结构化来源状态和缺失原因说明结果范围，采集数量不等同于全站岗位总量。

岗位发现不包含自动投递、定时采集或同平台多账号管理。

## 国聘

国聘标识为 `iguopin`，首版仅接入国聘官方岗位，不包含“知行订阅”。APP 二维码按官方格式生成，微信扫码使用官方返回的小程序码；两种方式共用官方凭证生成与状态轮询，认证结果还须通过官方个人账号接口校验。认证材料仅保留在该平台独立 Session 中。

搜索通过官网控件提交关键词和地区，接收匹配本次查询与页码的官方响应，并验证岗位所属来源。岗位 ID 保留十进制字符串，不转换为数字。多地点按官方列表保留；字段缺失不臆测，列表正文不直接标记为完整详情。城市代码采用官网的点分层级值，目录包含 373 个选项，详见 [城市目录维护](discovery-city-catalogs.md)。

官方真实空结果可以返回 `total=0、list=null`。适配器仅在总数确认是零、分页元数据有效时接受这种形式；总数非零、缺失列表、结构变化或验证响应仍按对应错误报告，不能推进为成功空批次。岗位排序、薪资准入、去重与保存沿用共享规则。

## 实习僧

实习僧标识为 `shixiseng`，仅搜索实习岗位，不包含校招。微信扫码使用官方小程序码；扫码确认后须通过官方个人账号校验，完成必要的绑定或验证。所有实时搜索、续查、详情及网页入口均执行后台登录校验，界面与 MCP 共用；账号校验网络异常不视为退出登录，也不放行采集。历史快照仍可读取。

创建二维码、轮询及扫码后的账号检查不发送 `X-Requested-With`；请求头遵循前述适配器声明规则。腾讯验证码预加载组件可能长期存在于正常页面，只有真实可见的验证或其他明确阻断证据才暂停采集，不自动完成或绕过验证。

搜索通过官网控件提交，响应必须匹配关键词、城市、实习类型和页码；成功提交批次后才推进页码。标题及薪资中的动态字体按当页官方 WOFF 的 cmap/post 字符映射解析，无法确认的字符不按猜测保存。岗位 ID 保留字符串；每周到岗天数和实习时长写入 JD，工作经验缺失时留空。日薪保留原值，不折算月薪；启用月薪区间时按通用规则排除日薪。

指定城市时，在字体解码后校验响应 `city`，按实习僧自身城市目录名称、官方名称和别名匹配，支持市后缀及市区分段，不使用地址子串匹配。多地点岗位包含所选城市即可保留原始多地点文本；地点缺失、无法确认或全部异地时不入库。未指定城市时保留官网地点结果。过滤后的空批次继续遵循官网分页，不视为解析失败或分页结束；原始可解析岗位身份保留用于预算、去重和无增长判断。缓存契约版本为 2，避免复用旧版本未过滤的采集缓存。该规则只在实习僧 adapter 执行，Repository 与客户端不增加过滤。

官方城市目录核验于 2026-10-09，包含 395 个城市级选项，查询参数直接使用官方名称，详见 [城市目录维护](discovery-city-catalogs.md)。国聘与实习僧都不增加平台或职业专用的相关性排序规则。
