# 岗位发现

本文档定义岗位发现的产品行为、查询规则、数据边界及 UI／MCP 契约。应用版本为 2.0.0，数据库版本为 v4，配置版本为 v1。数据库字段、索引及恢复校验见 [数据库文档](database.md)，跨进程接口以 `src/shared/job-discovery.ts` 为准。

## 功能与界面

岗位发现支持 BOSS 直聘、猎聘、智联招聘和前程无忧，提供统一搜索、岗位详情、网页浏览、账号管理、搜索历史及保存求职记录。侧栏入口位于公司管理与智能体之间，名称右侧显示 Beta 标识；应用默认启动页为求职记录。

页面标题右侧放置“账号管理”和“搜索历史”。标题下方采用可拖动分隔的左右布局：

- 左侧上方为关键词、地点、搜索按钮、平台选择和薪资筛选，下方为岗位列表、数量、排序、刷新及分页。关键词与地点并排，搜索按钮和薪资筛选按钮位于下一行。
- 右侧从标题下方开始，占满剩余高度，显示选中岗位的详情或网页。展开左侧薪资筛选不改变右侧高度。
- 窄窗口在列表与详情之间切换，保留岗位选择和列表状态。

搜索期间搜索按钮显示旋转图标和“取消搜索”，可点击取消；停止后显示“搜索岗位”，并提供“搜索更多岗位”。“薪资筛选”右侧使用一个 warning 按钮显示人工处理提示，例如“猎聘 · 需要网站验证”。仅需要登录、会话失效、需要网站验证三种状态按首次显示顺序排队；同时出现时沿用来源顺序，一次显示一项。解析失败、网络错误等仍显示普通来源错误，不进入人工验证队列。窄窗口保持按钮同行，长提示可省略显示。主搜索区域只展示结果总数，不展示来源采集计数或任务状态标签。搜索历史展示各平台岗位数及异常原因，完整任务状态保留给诊断及 MCP。

人工提示按原因打开对应界面：“需要登录”和“会话失效”打开该平台的扫码弹窗，直接复用账号管理右侧的二维码面板、刷新、扫码说明及额外验证逻辑，不展示左侧账号列表。取消、过期和失败保留原提示；官方扫码确认后自动关闭弹窗，并请求复核原搜索。主进程以当前 attemptId 的已认证状态校验复核请求，不凭 Renderer 或已有账号状态认定扫码成功。“需要网站验证”才打开独立平台网页，优先使用受阻页面和对应 Session；重启或历史页面已释放时打开该平台的官方账号入口。用户完成网站验证后手动关闭窗口。

扫码成功和网站验证关窗共用后续复核与续跑调度：应用沿全局 FIFO 和平台串行队列，使用相同会话和原搜索条件对该平台执行无缓存复核。复核期间保留当前提示并显示加载状态；只有收到可解析的官方批次且页面不再显示登录/验证阻断、数据成功提交后才清除提示，并自动继续该平台本轮搜索。复核首批计入同一轮的三批、200 条整批边界及 90 秒预算，不自动开启无限新轮次或重跑其他平台。页面重建时从官方查询恢复并按身份去重，不保证直接跳至原中断页。确认的真实空批次同样有效。不会仅凭关闭窗口、Cookie 变化或验证码暂时消失判定成功；首批复核仍被阻断、网络/解析/保存失败时保留提示。续跑再次遇到验证则停止并显示新提示；取消、关闭处理流程、退出登录、维护及退出都会中止待复核和续跑。其他人工提示按队列展示，当前轮次结束后可处理下一项，不自动开窗。

岗位提示和扫码登录的额外验证共用 `VerificationWindow` 窗口管理器，统一窗口创建、页面隔离、导航限制、互斥和释放；岗位验证可接管已有受阻页面。两种业务分别判断后续结果：扫码流程重试二维码，岗位流程复核原搜索。同一时间最多打开一个人工处理窗口，重复点击只聚焦已有窗口。网站验证窗口由用户关闭后触发岗位复核；扫码弹窗由官方扫码确认触发岗位复核。下一平台的人工处理窗口由用户主动打开。切换搜索、打开账号管理、退出对应平台、取消任务、维护或退出时关闭窗口并取消复核。人工操作期间不让自动采集操控该平台的页面。验证成功只解除对应来源的阻断，不自动完成整个搜索或继续其他平台。

平台勾选项以账号状态为准：仅 `authenticated` 的平台默认勾选并可操作，其余状态默认不勾选、灰色禁用。登录成功后自动勾选对应平台；退出、会话失效或需要验证时取消勾选并禁用。状态刷新保留用户对仍处于登录状态的平台所作的手动取消选择；查看历史也不重新勾选当前未登录的平台。未选择任何已登录平台时，界面不允许发起新搜索。

## 搜索条件

搜索条件仅包含关键词、可选地点、平台、最低月薪和最高月薪。

| 条件           | 规则                                                                                           |
| -------------- | ---------------------------------------------------------------------------------------------- |
| 关键词         | 必填，去除首尾空白，长度不超过 100 字符，通过各平台官方主搜索框提交。                          |
| 地点           | 默认空，可清除，无“全国”选项。指定地点通过官方地点控件提交；留空沿用网站默认地点，不表示全国。 |
| 平台           | 至少选择一个，可同时选择四个平台。                                                             |
| 最低／最高月薪 | 可分别省略，单位为人民币元；同时填写时最低值不得高于最高值。                                   |

地点目录是 `src/shared/discovery-cities.json` 中随应用发布的静态数据，共 363 个地点，包含四个平台的名称和代码映射。目录只收录四个平台共同支持的地点，界面使用单级城市列表，每个地点只显示一次，支持输入城市名称搜索。运行时直接读取静态目录，不联网生成或重新计算平台交集。不支持的地点明确返回来源错误，不回退为全国。

关键词和地点通过网站实际搜索请求提交，不按岗位文字再次筛选关键词。指定地点时，猎聘和前程无忧由各自适配器按岗位地点的城市部分精确匹配，排除异地、地点缺失及无法确认归属的岗位；支持目录名称和“市”后缀，不以地址任意子串判断。未选择地点时不做城市过滤。BOSS 和智联信任平台城市结果，不做本地城市过滤。保留官方主搜索列表的关键词相关匹配，排除独立推荐区域。查询前清除网站残留的高级筛选，并核验实际提交的条件。经验、学历、招聘类型和用工类型属于岗位展示信息，不作为搜索条件。

## 薪资准入与表示

薪资范围统一在入库前判断，不向平台下发远程薪资条件。任一上下限有值即启用筛选，采用区间相交规则，边界相等视为符合。

- 人民币月薪直接比较；人民币年薪除以 12 后比较，不按“13薪”等发薪月数调整。
- 单一金额按确定值比较，不把缺失上限解释为无限大。
- 日薪、时薪、外币、面议及无法可靠归一的薪资，在启用筛选时排除，并记录原因。
- 未设置薪资范围时，通用薪资准入不因薪资类型、缺失或解析失败而排除岗位。BOSS 适配器先检查会话：有效岗位缺少薪资文本时按会话失效处理，当前批次不入库。
- 被排除的新候选不新增岗位、观察或结果关联，也不删除其他搜索及求职记录中的既有数据。

观察保存薪资原文 `salary`，结构化数值仅包含人民币标准月薪下限 `salaryMin` 和上限 `salaryMax`。币种、周期、薪数及折算标记用于解析，不持久化。

| 原文示例                             | salaryMin | salaryMax |
| ------------------------------------ | --------: | --------: |
| 15–25K/月                            |     15000 |     25000 |
| 15000元/月                           |     15000 |        空 |
| 24万元/年                            |     20000 |        空 |
| 日薪、时薪、外币、面议或无法可靠归一 |        空 |        空 |

界面显示薪资原文。薪资排序使用上限，单值使用下限，不可比较值置后，同值按固定次序排列。

BOSS 搜索响应中，只要可解析的有效岗位缺少 `salaryDesc`、其值为空白或不是文本，就暂停该平台并显示“BOSS 直聘 · 会话失效”，点击进入扫码登录流程；已保存的批次保留。明确返回“面议”属于有效薪资文本，真实空列表不触发失效，非空列表全无有效岗位仍归入解析错误。当前查询响应已证实登录或验证阻断时，后续找不到搜索控件不会将其覆盖为“查询范围未验证”；其他真实条件核验错误仍保留原分类。

## 平台采集与任务执行

查询链路为：官方搜索 → 适配器逐条解析、去重及城市准入 → 标准化及薪资准入 → 整批事务入库 → SQLite 分页 → UI／MCP 展示。

### 适配器边界

`PlatformAdapter` 是平台功能的唯一接入契约。每个平台的业务实现集中在 `src/main/discovery/adapters/<平台>.ts`，包括：

- 官方搜索控件、条件提交、请求响应关联、字段解析、城市准入及分页。
- 岗位链接规范化、平台岗位 ID 提取、平台域名边界。
- 详情读取规则、账号登录证据、登录限制、安全验证和岗位下架识别。
- 二维码获取、轮询、确认、失效状态、接口请求头、协议解码和中英文扫码说明。
- 官方验证入口、验证页识别、允许的验证跳转、请求标识和来源地址。
- 账号检查地址、远程条件能力和独立的缓存契约版本。

| 文件                  | 查询与分页依据                                                                                    |
| --------------------- | ------------------------------------------------------------------------------------------------- |
| `adapters/boss.ts`    | 官方搜索框和城市控件，`joblist.json` 请求的 query/city/page，滚动加载与响应 hasMore。             |
| `adapters/liepin.ts`  | 官方搜索框和地点控件，`pc-search-job` 的 key/dq/currentPage，官方分页控件。                       |
| `adapters/zhilian.ts` | 官方搜索框和地点弹窗，搜索场景的关键词、城市与 pageIndex；条件一致的首屏 SSR 数据和续页搜索响应。 |
| `adapters/wuyou.ts`   | 官方搜索框和地点弹窗，清除地点后单选，`search-pc` 的 keyword/jobArea/pageNum，官方下一页。        |

共享层仅执行与网站无关的机制：浏览器和 Session 生命周期、安全边界执行、响应监听、DOM 操作、受限二维码请求与 Cookie 写入、取消与轮询、任务队列、去重与异常隔离、薪资标准化、事务和 SQLite 分页。公共 DOM 读取器接受适配器提供的选择器；适配器也可提供独立的页面脚本。共享层不包含具体平台 ID、网站域名、接口地址或按平台判断的业务分支。

二维码协议实例按登录尝试隔离。协议只获得受限请求和 Cookie 写入能力，不持有 Session、窗口或数据库。取消、失败、过期和登录完成时释放协议；已取消请求的晚到响应不得写 Cookie 或改变新尝试的状态。只有适配器提供并验证过的官方验证能力才可打开验证窗口，关闭窗口不视为登录成功。

`adapter-registry.ts` 只负责适配器注册，不承载网站规则。适配器不导入注册表、其他平台适配器、调度器、数据库或窗口管理器；共享依赖无运行时循环。架构测试约束这些边界。

适配器返回统一岗位、字段来源、实际条件、源页码、原始／有效／重复／异常数量和结束证据。共享批次模块接收适配器的岗位身份规则和准入函数，只处理去重、逐条异常隔离和日志，不自行决定某个平台的城市策略。

### 新增平台

1. 在 `adapters/` 新增一个实现完整 `PlatformAdapter` 的文件，包含该网站的搜索、详情、身份、登录及验证协议。
2. 在 `src/shared/job-discovery.ts` 的 `platformNames` 登记稳定 ID 和显示名称，在 `adapter-registry.ts` 登记适配器。平台类型、输入校验、选择框、账号卡片及 MCP 平台枚举从公共登记派生，无需逐处增加分支。
3. 为 `discovery-cities.json` 补充经核验的官方城市代码和名称。城市目录是静态交集数据，新增平台必须核验完整映射；不运行时猜测或静默替换城市。
4. 增加该平台的协议、身份、页面状态、取消和真实搜索验收。账号说明由适配器返回，Renderer 不增加专属文案键。改变解析或分页语义时更新该适配器的 `contractVersion`。

新增平台不需要修改搜索调度、二维码管理、详情服务、入库和分页流程。采集并发独立于已注册平台数量，最多四路，额外来源按队列执行。平台集合变化涉及数据库约束时，v2.0.0 发布前直接修正 v4，正式发布后通过新的数据库版本和正式迁移调整；注册不能绕过持久化校验。数据库 v4 只有一套当前确认的结构和接口，不接受开发中间态。

只有属于当前关键词、地点和页码的响应可被接收。条件无法确认、响应结构变化、翻页失败、登录限制、安全验证、超时和网络错误均返回明确来源状态，不能表示为成功的空结果。一个来源失败不撤销其他来源已保存的结果。单条岗位解析失败仅跳过该条并记录脱敏日志，不提示用户、不拒绝其他有效岗位。“页面解析未完成”仅用于当前响应无法按约定识别，或非空列表中没有任何可解析的有效岗位身份；真实空列表、部分坏条目及城市/薪资过滤后无结果不触发该警告。已提交批次的结果保留。“平台响应超过读取限额”“岗位批次数量校验失败”及响应体读取失败归入“网站请求失败”，保留各自固定原因用于诊断。

任务遵循以下规则：

- 全局 FIFO 调度，同平台串行，最多四个平台并行。
- 每轮 90 秒，每平台最多三批；200 条有效候选作为整批边界停止预算，按城市和薪资过滤前可解析、批内去重后的候选数量计算。已返回的批次完整处理。
- 整批岗位与来源进度在同一事务内保存，成功后推进游标；保存失败保留待提交批次。
- 连续两批来源身份无新增、且无明确结束证据时标记部分完成。全部候选被城市或薪资过滤不构成分页结束或无增长。无增长判断使用过滤前的来源身份；非空批次全部条目解析失败时停止该来源并报告解析错误，不据此宣称网站已结束。
- 取消保留已入库结果。重启将未完成任务标记为中断，不直接复用失效的浏览器游标。

列表缓存有效期为两分钟，保存连续批次，按平台、关键词、地点、薪资条件、会话代次及适配器契约隔离。浏览器查询上下文在采集轮次之间保留；上下文失效时重新提交官方查询，按来源身份去重恢复，并返回恢复状态。

“搜索更多岗位”使用同一任务和条件继续下一轮采集，不批量补全详情。来源的已提交页码或游标决定下一批；网站结束由响应或分页控件证据确认，不用页码乘当前页条数推算。

## 结果展示与稳定分页

搜索期间，界面约每 1.6 秒读取任务和数据库结果。各平台整批入库后即可显示，不等待所有来源完成。界面翻页只读取 SQLite，不触发网站采集。

界面的 `discovery:list` 与 MCP 的 `list_discovered_jobs` 共用 `JobDiscoveryService.list()` 和同一套 Repository 查询，均支持相关性、月薪和发现时间三种排序。首次读取结果建立浏览视图 `viewId`，并固定岗位序号和观察版本。后续新增岗位追加到末尾；采集结束、详情补全不自动重排已有岗位或改写视图观察。

- 主动刷新或改变排序建立新视图并回到第一页。
- 每页支持 10、20、50 条，默认 20 条；改变每页条数保留视图并回到第一页。
- 后续页必须携带相同 `viewId`，同一视图不能改变排序。
- 省略排序参数时沿用已有视图排序；仅创建新视图时默认按相关性排序。
- 计数与分页使用相同视图条件，不执行关键词、地点或薪资筛选。
- 不同客户端可继续读取各自视图；所属搜索历史删除时一并清理。

## 岗位身份、观察与详情

岗位身份优先使用平台岗位 ID，缺少 ID 时采用平台规则验证的规范 URL。同平台按身份去重，跨平台不自动合并，仅提示疑似重复。猎聘普通岗位与校园岗位区分身份；平台 ID 中的合法字符原样保留。

岗位观察不可变，搜索结果和浏览视图引用具体观察版本，岗位持有当前观察引用。完整标题、公司和城市生成非唯一指纹，通过索引查找跨平台疑似重复；字段不完整时不生成指纹。

只有用户打开某个岗位时，界面才使用 `mode=ensure` 按需读取详情。共享 Service 根据岗位当前观察的详情时间复用三十分钟缓存，不能用固定视图中的旧观察判断缓存有效期；有效缓存无需启动桌面浏览器。`mode=snapshot` 只读取指定观察，`mode=refresh` 强制读取网站。首次搜索、后台轮询、翻页和列表刷新不自动选择岗位或读取详情。单次网站读取预算为 25 秒。列表刷新保留已读完整 JD，不延长详情缓存有效期。

详情显示岗位、公司、地点、薪资原文、经验、学历、JD、来源和读取时间。缺失原因区分未登录、会话失效、网站验证、平台未提供、解析失败及尚未读取详情。切换岗位后，过期响应不得覆盖当前选择。

登录和验证的页面文字证据只取可见且位于 JD、推荐区域之外的内容，避免把职责描述中的“安全验证”等文字误判为网站阻断；真实验证标题、网址和验证码 iframe 仍独立检查。

列表摘要即使包含 JD 文字，也保留未读取完整详情或被阻断的原因；网页模式切换岗位立即导航，不依赖详情读取成功。

详情补全生成新观察并重新标准化。若薪资不符合当前搜索条件，保存新观察并移除当前结果关联；旧视图仍可读取和保存其固定观察，刷新后应用变化。

### 岗位下架

实际读取详情时，只有同一岗位的明确状态节点表示下架、关闭、失效、过期或删除，才执行下架清理。JD 正文、推荐区域、登录页、验证码、网络错误、空白页、泛化 404 和跳转到其他岗位不能作为下架证据。

确认下架后，在同一事务中删除发现岗位、全部观察、搜索结果、浏览视图条目及保存来源关联，重算相关来源数量。已有求职记录和公司保留。

界面立即移除左侧岗位，右侧只显示“已下架”，不自动选择其他岗位。当前页为空时回到最后一个有效页，其余岗位顺序和固定序号不变，序号允许留空。当前运行期间拦截该身份的旧批次并清理缓存，防止旧响应重新写入。MCP 返回 `DISCOVERY_JOB_OFFLINE`。缓存详情不代表平台实时状态，清理仅发生于实际读取并确认下架时。

## 保存与历史管理

保存岗位时，用户选择已有公司或确认新建公司，指定现有状态及可选简历。公司、求职记录和来源关联在同一事务中保存。重复保存同一来源岗位返回既有关联；后续采集不覆盖用户编辑。不推断公司行业，也不将岗位工作地点写成公司办公地点。

搜索历史保存查询条件、实际远程条件、来源状态及结果观察版本，支持查看、单次删除和批量删除。进行中的任务先取消再删除。关键词旁仅显示非空地点标签，不显示任务状态标签。平台明细保留平台名称和岗位数量，仅在需要登录、会话失效、需要网站验证、此城市尚未支持、查询范围未验证、页面解析未完成、超过本轮时间预算、网站请求失败这八种异常状态下追加原因；不显示排队中、搜索中、完成、部分完成、已取消、已中断。

删除历史同时删除所属浏览视图，再按实际引用回收岗位和观察。搜索结果、旧视图、保存关联及仍有业务引用的岗位当前观察属于有效引用；当前观察指针不能使孤立岗位永久保留。历史清理不删除求职记录，求职记录删除后的来源关联清理同样触发引用回收。

## 账号与会话

账号管理和搜索历史弹窗固定为窗口宽 70%、高 80%。账号管理左侧四个平台以两行两列排列，右侧显示所选平台二维码或账号状态，底部为关闭按钮。每个平台支持一个账号。

账号卡片提供“查看状态”（未登录时为“扫码登录”）和“退出登录”。退出登录按钮与状态按钮尺寸一致，有边框、背景透明。已登录面板显示成功状态和上次确认时间。

点击扫码登录时请求平台二维码，正常流程只展示二维码。刷新、切换平台和关闭弹窗取消旧二维码请求。登录成功依据官方确认响应或账号页面证据判断，窗口关闭、Cookie 变化及二维码生成成功均不代表已登录。

猎聘要求人工验证时提供“打开猎聘验证”。用户主动打开官方窗口、完成验证后返回账号管理重试二维码。验证窗口复用该平台 Session，使用官方 URL，不添加应用后缀，网站自身参数原样保留。四平台 Session、页面和两类验证窗口的 User-Agent 不含职迹／JobTrail／zhiji 产品名，保留真实 Chromium／Electron 版本；远程页面不提供业务 preload、不注入应用标识，窗口标题仅使用网站名称或标题。前程无忧二维码 JSONP 使用中性回调名 `callback`，不在请求参数中携带应用名称。不自动完成或绕过网站验证。

Chromium 将认证材料保存在 `browser-sessions/<platform>`。Cookie、LocalStorage 和 IndexedDB 不写入配置或业务数据库，不进入可移植备份；二维码和临时认证响应不写入诊断日志。数据库仅保存平台状态、证据、确认时间和会话代次。

普通重启保留确认状态，界面显示“已登录”；搜索遇到登录失效或验证限制时提示用户处理。备份恢复撤销导入的确认状态，复核本机会话。退出登录经确认后停止该平台采集、释放页面并清除其本地 Session，不自动请求新二维码。

官方扫码确认成功时递增会话代次，后续搜索不复用匿名或旧账号的查询缓存。普通页面状态复核保留当前代次。

## 内置浏览器与安全边界

右侧岗位网页使用 Electron `WebContentsView` 和应用自带 Chromium，在详情与网页模式之间切换，支持返回、前进、刷新、缩放和外部打开。切换岗位保留当前模式并导航至新岗位。

后台采集使用隐藏 `BrowserWindow`。同平台登录、验证、采集和岗位网页共享 Session，页面实例独立。远程页面不加载业务 preload，关闭 Node 集成，开启上下文隔离和沙箱，拒绝权限申请及下载，限定导航和公网网络访问。

公共网络校验允许的 URL 长度上限为 10240 字符，超过上限仍拒绝；仅允许 HTTP/HTTPS 和 80/443 端口，禁止内嵌凭据，并执行公网地址检查。URL 长度与响应体读取限额、岗位采集批次预算分别校验。

Vue 上报网页占位区域和固定浏览操作，由 Main 管理原生视图。弹窗、下拉菜单和页面切换协调隐藏或恢复原生视图，防止遮挡应用控件。

### 发布约束

所有平台 Session 在使用前配置本机固定代理，并清除旧连接；Chromium 不得绕过代理访问回环地址，也不得失败后直连。代理为每次新连接校验 DNS 结果并固定数字 IP，拒绝包含内网地址的混合结果，不缓存“允许访问”的布尔值。HTTPS 通过 CONNECT 保留端到端 TLS、证书校验、SNI 和 Chromium Cookie；HTTP 仅允许 80 端口，CONNECT 仅允许 443。页面、子资源、Service Worker、扫码请求和验证窗口共用该连接边界，远程页面禁用不经代理的 WebRTC UDP。

系统/PAC 代理支持 DIRECT 和 HTTP/HTTPS 代理；上游代理接收已校验的数字 IP，不重新解析目标域名。用户配置的上游代理属于可信网络设施。SOCKS、需要认证或拒绝 IP CONNECT 的代理不受支持，连接失败时不会自动换代理或直连。备份、更新和退出释放连接，恢复时重新配置。连接层单元测试由 `pnpm test` 执行，真实安装包隔离测试纳入 `pnpm test:discovery:local` 和 `pnpm release:win`。

真实平台验收尚未覆盖四平台的完整扫码登录、人工验证、搜索、续查和 JD 读取链路。智联已登录搜索与续查已通过专项验收；BOSS 匿名响应解析、猎聘分页及验证、前程无忧受限详情仍需完成对应验收。合成页面、二维码解码、单个平台的列表成功均不能替代完整平台验收。

## 数据库与生命周期

数据库 v4 包含十张岗位发现业务表：

| 表                       | 职责                                                         |
| ------------------------ | ------------------------------------------------------------ |
| `discovery_jobs`         | 来源身份、规范 URL、当前观察及疑似重复指纹。                 |
| `discovery_observations` | 不可变的原始字段、标准化字段、字段来源、缺失原因及读取时间。 |
| `discovery_runs`         | 查询条件、任务状态和搜索历史。                               |
| `discovery_requests`     | 请求 ID 与任务的幂等映射。                                   |
| `discovery_sources`      | 各平台进度、实际条件、批次统计、游标和错误。                 |
| `discovery_results`      | 当前任务准入岗位、观察引用及相关性。                         |
| `discovery_views`        | 搜索浏览视图、排序和创建时间。                               |
| `discovery_view_items`   | 视图内固定序号、岗位及观察引用。                             |
| `discovery_platforms`    | 平台确认状态和能力信息。                                     |
| `discovery_saved`        | 发现岗位与求职记录的保存关联。                               |

观察 JSON 上限为 128 KiB UTF-8 字节，写入、数据库约束和备份恢复采用相同边界。超限明确失败，不截断 JD 后标记为完整详情。关联完整性由 Service 事务和恢复校验维护，不使用数据库触发器或物理外键。

结构、引用和来源计数校验在同一 SQLite 读事务快照中完成，允许 MCP 在另一个连接提交数据时安全启动桌面。

正式数据库 v1／v2／v3 通过注册迁移升级到 v4。产品只接受最终字段契约，不包含未发布结构之间的兼容接口或启动自动修补。

备份、恢复、升级和退出前停止任务准入，取消并等待采集及扫码，关闭页面、刷新 Session，再执行数据库流程。

## MCP 与智能体

UI、外部 MCP 和内置 Agent 共用 `JobDiscoveryService` 及工具注册表。查询、薪资准入、分页、详情和保存规则一致。

| 工具                      | 契约                                                                                                                                                                       |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `get_job_platform_status` | 获取平台状态、能力和限制；`check=true` 主动复核。                                                                                                                          |
| `start_job_search`        | 接收关键词、可选地点、平台和可选薪资范围，按 `requestId` 幂等创建任务。                                                                                                    |
| `get_job_search`          | 获取任务状态、来源进度、实际条件、覆盖及错误。                                                                                                                             |
| `list_discovered_jobs`    | 按 `runId`、`viewId`、排序和分页参数读取结果，不执行业务筛选。                                                                                                             |
| `continue_job_search`     | 按同一条件继续下一预算轮。                                                                                                                                                 |
| `cancel_job_search`       | 取消指定任务，保留已保存结果。                                                                                                                                             |
| `get_discovered_job`      | `mode=snapshot` 读取指定观察；`mode=ensure` 按需补全并复用最新有效详情缓存；`mode=refresh` 强制重新读取。支持 `viewId`／`observationId`，返回 `removedFromCurrentSearch`。 |
| `list_job_search_history` | 分页读取本地历史，不要求桌面运行。                                                                                                                                         |
| `save_discovered_job`     | 经 MCP 写入确认后，事务保存公司、求职记录及来源关联。                                                                                                                      |

实时操作通过 Windows 命名管道交给 Electron Main，通信绑定安装目录、协议版本和每次启动的随机令牌。优先连接已打开客户端，不改变窗口状态；无可连接客户端时才通过根启动器启动到托盘。并发启动合并，子进程清除 `ELECTRON_RUN_AS_NODE`。

实时采集不进入普通本地只读工具并行集合。MCP 不暴露 Cookie、二维码、任意页面脚本或浏览器控制。人工登录和验证返回平台提示及恢复指引，不无限等待。工具以结构化来源状态和缺失原因说明结果范围，采集数量不等同于全站岗位总量。

岗位发现不包含自动投递、定时采集或同平台多账号管理。
